How it works

Fire-and-forget. Zero latency added to your agent.

RUNNING

Your agent runs normally

The decorator wraps the function. Nothing about your agent's logic changes.

PENDING

Synathic checks Postgres, async

After the call returns, we verify the postcondition in a background task — off the request path.

PASS / FAIL

You see reality, not the agent's word

Row exists → pass. Row missing → fail, visible in seconds instead of a support ticket.

Questions

Before you ask.

Does this add latency to my agent?

No. The decorator returns immediately. Verification runs as a background task, off the request path — your agent never waits on it.

What databases do you support?

PostgreSQL today. MySQL and REST endpoint checks are next, based on what design partners actually need.

How is this different from just logging?

Logs show what your agent attempted. Synathic checks what the database actually did — a clean log doesn't mean the write landed.

Do I need to change my agent's code?

No. You wrap the function you already have with one decorator. The logic inside stays exactly as it is.
